# NixOS Flake Configuration

A modular NixOS configuration for three machines:

* **Flakes** for reproducibility.
* **Home Manager** for user environment management.
* **Modular Design** to share config between machines.

## 📂 Structure

```text
~/nix-config/
├── flake.nix             # Entry point: defines inputs & machine outputs
├── flake.lock            # Pinned versions (source of truth)
├── modules/              # Reusable, host-independent logic
│   ├── nixos/
│   │   ├── desktop/      # Compositors, DMS, shared Wayland services
│   │   ├── hardware/     # Drivers and independently selectable hardware features
│   │   ├── services/     # System services and runtime compatibility
│   │   └── users/        # Shared NixOS/Home Manager user integration
│   ├── home-manager/
│   │   ├── features/     # Individually selectable tools and compositors
│   │   └── profiles/     # Core, development, graphical, and headless bundles
│   └── shared/           # Settings valid in both NixOS and Home Manager
└── hosts/                # Machine-specific configurations
    ├── ganymede/         # Hostname: ganymede (desktop, dual-boots mimas)
    │   ├── default.nix   # System entry point
    │   ├── home.nix      # User entry point (Imports HM profiles)
    │   └── hardware-configuration.nix # Autogenerated hardware info
    ├── europa/           # Hostname: europa (mini PC)
    │   ├── default.nix   # System entry point
    │   └── home.nix      # User entry point
    └── thebe/            # Hostname: thebe (WSL guest, runs inside mimas)
        ├── default.nix   # System entry point (WSL-specific)
        └── home.nix      # User entry point
```

## ⚡ Cheatsheet

**Check Build (No Sudo):**

> **Tip:** Run `hostname` in your terminal to see your current hostname. Replace `#ganymede` with `.#<your-hostname>` below.

```bash
# Check for build errors without creating the 'result' symlink
# Example for the desktop:
nixos-rebuild build --flake .#ganymede --no-link
# Example for WSL:
nixos-rebuild build --flake .#thebe --no-link
```

**Apply Changes (System & Home):**

```bash
sudo nixos-rebuild switch --flake .#ganymede
```

Home Manager is integrated into each NixOS generation rather than exposed as
a second standalone configuration. This ensures the system and home use the
same nixpkgs instance, overlays, and activation lifecycle.

**Clean Garbage (Free disk space):**

```bash
# Delete older generations
sudo nix-collect-garbage -d

```

## 🔄 Updates & Maintenance

### How to Update

Updates are manual and explicit. Nothing changes until you run these commands.

1. **Update the Lockfile** (Downloads latest package versions):
```bash
nix flake update

```


2. **Apply the Update**:
```bash
sudo nixos-rebuild switch --flake .#ganymede

```


3. **Commit the State**:
```bash
git add -A
git commit -m "chore: update system inputs"

```



### 🚑 Recovering from Breakage

If an update breaks your WiFi, Graphics, or Config:

**Option A: Rollback via CLI** (If you can still use the terminal)

```bash
sudo nixos-rebuild switch --rollback

```

**Option B: Rollback via Boot Menu** (If the system won't boot)

1. Reboot the computer.
2. In the systemd-boot menu, select the entry below the current one (e.g., `NixOS - Generation 44`).
3. The system will boot into the exact state it was in before the update.

## 🛠 Workflows

### 1. How to Add Packages

* **One host only:** Add it under `hosts/<host>/`.
* **Reusable user feature:** Add it under `modules/home-manager/features/`.
* **User package bundle:** Add it to a profile under `modules/home-manager/profiles/`.
* **System driver/service:** Add it under `modules/nixos/hardware/` or `modules/nixos/services/`.
* **Shared desktop infrastructure:** Add it under `modules/nixos/desktop/`.
* **Unfree support:** It is enabled centrally in `modules/nixos/base.nix`.

### 2. How to Add a New Machine

1. Create `hosts/new-machine/default.nix` and `home.nix`.
2. Generate `hosts/new-machine/hardware-configuration.nix` on the machine.
3. Compose only the capabilities that machine needs.
4. Add the host to the `nixosConfigurations` set in `flake.nix`.
5. Build with `nixos-rebuild build --flake .#new-machine --no-link`.

Keep physical topology—filesystems, monitors, power limits, and hostnames—in
the host directory. Reusable modules should describe one capability and avoid
detecting unrelated capabilities implicitly.

### 3. Proprietary Apps (Antigravity/Jetski)

If an app isn't in Nixpkgs or fails to build:

* **Option A:** Use **Flatpak** (`flatpak install ...`).
* **Option B:** Use **Steam-Run** (`steam-run ./my-binary`).

## ⚠️ Important Gotchas

**1. "Path does not exist" Error**
Nix Flakes only see files that are **tracked by git**.

```bash
git add .

```

**2. Permission Denied**

* Use `sudo` for `nixos-rebuild`.
* Do **NOT** use `sudo` for `git` commands.

**3. State Versions**

`system.stateVersion` and `home.stateVersion` are compatibility baselines from
the machine's initial configuration. Do not bump them during normal updates.

**4. Home Manager & Nixpkgs Overrides**

Home Manager uses the host's global package set. Put `nixpkgs` configuration
and overlays in NixOS modules, not in `home.nix`.
